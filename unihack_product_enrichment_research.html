01Manufacturer / Brand Entity Resolution

The core modeling error is treating manufacturer, legal company, parent brand, sub-brand, distributor code, and product brand as one string. Use a graph with typed relationships, not a single canonical-name column.

Best pattern for the example: parse the noisy field and description into mentions; generate candidate entities with high-recall blocking; score the pair with lexical, embedding, catalog, and web-evidence features; then resolve brand and manufacturer independently. A record may resolve to Diablo as product brand, Freud Inc. as legal/manufacturing parent, and a distributor code as source metadata.

Query Brand Entity Linking in E-Commerce Search

What

Amazon research for very short queries averaging 2.4 words. It compares a two-stage NER plus matching system with Q2E-PECOS extreme multi-class classification, then fuses the signals.

Why here

It directly addresses surface variants, multilingual forms, abbreviations, and parent/sub-brand relationships. The online fusion experiment improved brand recall by 11.0% in one store cluster and 5.44% in another, with small engagement and profit lifts.

SOTA path

Build a brand mention detector, ANN candidate index, and typed brand graph. Train pair scoring on hard negatives such as parent vs sub-brand and similarly named distributors. Calibrate the auto-accept threshold on a cost-weighted holdout; abstain on unresolved hierarchy.

DoorDash product knowledge graph

What

A production engineering writeup that explicitly models manufacturer, parent brand, and sub-brand as separate nodes. Their ingestion pipeline uses an in-house classifier, LLM extraction for cold-start misses, graph retrieval, duplicate checking, and classifier retraining.

Why here

This is the cleanest precedent for the Diablo/Freud distinction. It also demonstrates a pragmatic human-in-the-loop loop rather than pretending a general LLM knows every brand.

SOTA path

Represent brand_of, owned_by, manufactured_by, and distributed_by as distinct edges with evidence and dates. Retrieve similar graph nodes before deciding whether a new mention is an alias, child brand, or new entity.

BrandNERD public dataset and pipeline

What

An open brand NER/normalization pipeline with more than 390,000 raw brand names. It canonicalizes noisy variants, collects web evidence, applies similarity analysis, and includes a verification stage plus reviewable intermediate artifacts.

Why here

Useful bootstrap data for alias generation and a credible explanation of how the canonical brand table grows. It is not a substitute for official manufacturer evidence.

SOTA path

Use it only for candidate generation. Re-verify every production alias on an official manufacturer domain, store the evidence URL and capture date, and maintain a negative alias list to prevent false merges.

Splink probabilistic record linkage

What

A maintained Python package implementing Fellegi-Sunter linkage with unsupervised EM training, SQL/DuckDB execution, scalable backends, and cluster/graph diagnostics. It supports jobs from laptop scale to very large datasets.

Why here

It provides interpretable match weights and a defensible baseline for manufacturer and brand aliases. It is stronger than a raw fuzzy score because agreement and disagreement on each field have learned evidence weights.

SOTA path

Use multi-pass blocking: normalized token, MPN prefix, brand phonetic key, embedding ANN, and official-domain key. Add typed relationship constraints and graph-level cluster checks; optimize precision separately for auto-merge and recall separately for candidate recall.

RapidFuzz plus Entity Embed

What

RapidFuzz supplies fast C++ string metrics and top-k extraction. Entity Embed turns company/product records into vectors for approximate-nearest-neighbor blocking and reports roughly 0.99 recall on several datasets while explicitly trading precision for recall.

Why here

Use deterministic matching for cheap obvious aliases, then embeddings to avoid missing hard variants such as punctuation, transliteration, or appended legal suffixes.

SOTA path

Do not let either tool make the final merge. Fuse exact normalized fields, character similarities, MPN compatibility, embedding similarity, graph relationship features, and official-site evidence in a calibrated classifier.

Wikidata organization hierarchy and Open Product Data Brand Manager

What

Wikidata provides properties such as parent organization (P749), owned by (P127), brand (P1716), and official website (P856). Open Product Data offers an open brand repository with stable BSIN identifiers and API/bulk access. The Wikidata Companies Graph is another exportable graph.

Why here

These are useful priors for parent/sub-brand candidate generation when the incoming field is wrong or incomplete.

SOTA path

Use them as weak priors and alias sources only. Prefer official manufacturer pages/PDFs for the final production edge, preserve source provenance, and attach temporal ownership because acquisitions make static parent mappings stale.

Recommended data model: every entity has a stable internal ID, preferred label, aliases, entity type, official domains, and a typed edge list. Every edge has source URL, snippet/span, observed date, confidence, and status: proposed, verified, contradicted, or retired.

04Multi-Agent / Agentic Pipeline Design

Use agents where the search space is uncertain, but keep the state machine deterministic. The high-quality pattern is parallel evidence gathering followed by targeted verification, not one autonomous agent with a giant prompt.

INFOGENT: Navigator, Extractor, Aggregator

What

A modular web-information framework that separates website discovery, page extraction, and aggregation. It supports both API-driven and interactive visual access and reports a 7% gain over a prior multi-agent framework on FRAMES plus a 4.3% gain on AssistantBench.

Why here

This maps cleanly to manufacturer discovery, official-site browsing, spec extraction, and final record assembly while keeping each role testable.

SOTA path

Replace the generic aggregator with an evidence ledger. Navigator proposes only official-domain hops; extractor emits field candidates with spans; aggregator joins by MPN and resolves conflicts. Log every action and retry reason.

Argus evidence assembly

What

A 2026 preprint that maintains a shared evidence graph. A Navigator detects missing claims, dispatches targeted Searchers, verifies the graph, and synthesizes only after the graph is complete. With 8 parallel Searchers it reported a 12.7-point average gain over a single-searcher baseline; 64 Searchers reached 86.2% on BrowseComp.

Why here

Product enrichment is naturally a set of claims: brand, MPN, dimensions, grit, pack count, and category-defining facts. Missing one required claim should trigger a targeted search, not a whole-pipeline restart.

SOTA path

Make each required attribute a graph node with states supported, contradicted, not-found, and pending. Dispatch searches only for unresolved nodes; parallelize independent manufacturer-page and PDF retrieval.

DeepResearcher

What

An end-to-end RL-trained deep research agent. The reported gains reach 28.9 points over prompt-engineering baselines and 7.2 points over RAG-based RL agents; qualitative behavior includes planning, cross-validation, self-reflection, redirection, and honest failure.

Why here

It supports the case for multi-pass research rather than single-shot browsing, especially when a manufacturer site has inconsistent navigation and multiple PDF versions.

SOTA path

You do not need to train RL for the hackathon. Reproduce the behavior with explicit policies: plan, search, inspect, extract, cross-check, retry, and abstain. Save trajectories so a judge can see the recovery behavior.

FineVerify

What

A fine-grained self-verification method that decomposes a candidate into checkable sub-questions and labels each check supported, not_found, or contradicted. Four sampled trajectories improved GPT-5-mini by 8.2 points and Gemini-3-flash by 5.6 points on average in the reported benchmarks.

Why here

Do not ask a judge model whether a whole product record "looks right." Ask whether this exact value is supported by this exact evidence and whether it conflicts with another source.

SOTA path

Run two independent extraction passes, then verify every disagreement and every high-impact field. Weight MPN, brand, dimensions, and pack count more than marketing copy. Stop early when all required checks are supported.

LangGraph, Haystack Agents, and LlamaIndex Workflows

What

Maintained orchestration options for stateful graphs, retryable nodes, tool loops, persistence, interrupts, and multi-agent composition. LangGraph is explicitly designed to mix deterministic nodes with LLM-driven nodes.

Why here

The evaluator-uploaded file, source allowlist, evidence ledger, and final JSON are durable state. A graph runtime makes the demo reliable and lets you show retries and human-review checkpoints.

SOTA path

Use a typed state object and idempotent nodes: parse, resolve, classify, plan sources, fetch, parse documents, extract, verify, generate, validate, publish. Add timeouts, caching by URL hash, retry budgets, and an interrupt for review.

FineVerify code and data plus INFOGENT code

What

Both projects expose reproducible implementations rather than only conceptual papers. FineVerify includes trajectory sampling, verification scoring, early stopping, and parallel processing; INFOGENT provides modular navigator/extractor/aggregator code.

Why here

Borrowing their decomposition gives a concrete implementation plan and a credible reason to claim multi-agent design without hand-waving.

SOTA path

Adapt the interfaces to the manufacturer-only policy and include a deterministic domain filter. Do not let a third-party marketplace result enter the evidence store even if it ranks highly.

Ensemble rule: diversity matters more than simply repeating the same call. Use different prompts or models for candidate extraction, a deterministic parser for units, and a verifier that sees the evidence but not the first model's rationale. Majority vote is a fallback; evidence-grounded agreement is the primary signal.

05Description Generation Under Strict Constraints

Treat each description as a compiled artifact from verified facts. Generate only after extraction is frozen, and treat character counts, casing, field order, and forbidden claims as executable tests.

Grammar-Constrained Decoding for Structured NLP Tasks

What

An EMNLP paper showing grammar-constrained decoding can improve structured information extraction and entity disambiguation, in some settings outperforming unconstrained models and task-specific fine-tuned models without fine-tuning.

Why here

It supports using formal constraints for output shape and field order when exact compliance is part of the score.

SOTA path

Define grammars for the five output templates, allowed casing, separators, and optional sections. Keep semantic facts outside the grammar and run a validator after decoding.

Grammar-Aligned Decoding and DOMINO

What

These works warn that naive constraints can distort the model distribution. Grammar-Aligned Decoding introduces sampling ideas to reduce quality loss; DOMINO focuses on subword-aligned constraints and reports low overhead with speedups in some settings.

Why here

Strict formatting should not make the copy robotic or semantically worse. A winning implementation must protect both compliance and product fidelity.

SOTA path

Use constraints for structural tokens and post-generation editing for prose. Benchmark constrained versus unconstrained-plus-validator output on factuality, readability, and exact compliance.

TruncProof

What

A grammar-constrained method designed to produce valid outputs under a hard token limit by estimating the minimum completion budget during LL(1) decoding.

Why here

Character limits are not token limits, but the same idea applies: reserve space for required suffixes and avoid generating a string that cannot finish legally.

SOTA path

Implement an exact character-budget controller for the final renderer: tokenize only for generation, count Unicode code points after normalization, reserve mandatory fields, and use deterministic shortening strategies before asking the model to regenerate.

Stick to Facts: Fidelity-oriented Product Description Generation

What

FPDG uses entity labels and a keyword memory so generation remains anchored to product attributes; the paper reports a 25% fidelity improvement and up to 89.72% entity-word content in input keywords.

Why here

Descriptions should be generated from verified attributes, not from the raw noisy title. This is especially important for industrial claims such as grit, dimensions, compatibility, and pack count.

SOTA path

Represent facts as typed slots and make each variant use an explicit slot whitelist. After generation, extract claims back out and require every claim to map to a verified fact; remove unsupported adjectives and promises.

BAML schema-aligned parsing, Outlines, and Instructor retries

What

Practical structured-output approaches: schema-aligned parsing tolerates common malformed output, Outlines constrains regex/JSON/grammar generation, and Instructor re-asks after validation failures.

Why here

Use the strongest mechanism available for the model path, but keep the final guarantee in ordinary code. A length validator is more trustworthy than a prompt saying "stay under 80 characters."

SOTA path

Generate candidate text, run formula/regex/length/fact checks, then repair using a deterministic ladder: remove marketing modifiers, compress units, remove optional slots, regenerate with remaining budget, finally abstain if required facts cannot fit.

Recommended variant compiler

Mobile: brand + MPN + product type + one differentiator.

Invoice: compact, unambiguous noun phrase; no marketing.

Long: verified attributes in fixed order with UOMs.

Retail: scannable benefits derived from facts.

Marketing: persuasive tone, but every technical claim must be traceable.

Hard compliance test

Normalize whitespace and casing, count characters, validate exact field order, assert no forbidden claims, assert required tokens, and compare extracted claims to the approved fact set. Store pass/fail per variant, not just a global score.

06Data Quality, Validation, and Self-Evaluation

The impressive answer is not "the model is 98% confident." It is a calibrated risk-coverage curve: at an agreed error budget, how much of the catalog can be auto-published, and which fields are escalated?

Conformal Alignment

What

A distribution-free framework for deciding when to trust already-generated foundation-model outputs, with finite-sample control of the false discovery rate among accepted outputs.

Why here

It gives a rigorous foundation for auto-accept, review, and reject bands instead of arbitrary confidence cutoffs.

SOTA path

Fit thresholds on a held-out labeled set, separately for brand, classpath, and each high-risk attribute. Report coverage at 1%, 2%, and 5% field error budgets; recalibrate when source distribution changes.

HUMO human/machine cooperation for entity resolution

What

A quality-control framework that assigns machine decisions and human review to minimize review cost subject to precision/recall requirements.

Why here

It directly supports the review queue story: uncertain brand hierarchy or conflicting manufacturer evidence should be routed to a person, not hidden.

SOTA path

Define asymmetric costs: false brand merge is worse than a missed alias; wrong MPN/dimension is worse than absent enrichment. Optimize review allocation by expected error reduction per minute.

FUSER uncertainty-calibrated ER

What

A few-shot entity-resolution method that enriches pairs with structural attributes using LLMs and adds uncertainty calibration. It reports gains on six ER benchmarks, works with as few as 50 labeled positive samples, and a 10x speedup in uncertainty quantification.

Why here

Useful when the hackathon ground truth is small. Enriching records with extracted structure can make company/brand matching easier, but hallucinated enrichment must be discounted.

SOTA path

Use only evidence-grounded structural fields as match features. Calibrate a pair score on the small labeled set and compare against Splink and a cross-encoder; keep uncertainty features separate from raw model confidence.

SynthAVE multi-LLM arena validation

What

A 2026 preprint evaluates synthetic attribute labels across 12,726 products, 229 product types, 792 attributes, and four languages. Twenty-one judge configurations reached Cohen kappa 0.92 with human experts, versus Fleiss kappa 0.76 across individual judges.

Why here

It is a strong precedent for using diverse judges to validate labels at scale, while still comparing the ensemble against human annotations.

SOTA path

Use 3-5 diverse judge configurations only on disagreements and high-impact fields. Require a majority plus evidence support; do not treat judge agreement as truth without a small human audit.

RAGAS faithfulness and context precision

What

RAGAS defines faithfulness as supported claims divided by total claims and context precision as whether relevant retrieved chunks rank above irrelevant chunks.

Why here

These metrics separate retrieval failure from generation failure, which is exactly what a manufacturer-only pipeline needs to diagnose.

SOTA path

Adapt them to field-level claims: evidence retrieval recall@k, exact span support, normalized-value accuracy, contradiction rate, and unsupported-claim rate. Use rules for numeric facts and an LLM judge only for semantic entailment.

MAVE benchmark and WDC Products

What

MAVE contains 2.2 million products, 3 million annotations, and 1,257 categories for multi-source attribute extraction. WDC Products contains 11,715 offers describing 2,162 product entities and tests pairwise and multi-class matching under corner cases, unseen entities, and different training sizes.

Why here

They provide external baselines and hard-case ideas, but they do not replace a manufacturer-only, industrial ground-truth set.

SOTA path

Use them for smoke tests and model selection. Build the real benchmark from evaluator-like industrial records with official source evidence and manually adjudicated values; keep train/dev/test manufacturer-disjoint.

Benchmark judges will trust: freeze a 50-200-row gold set before tuning; double-label the hard rows; report agreement, exact and normalized field accuracy, macro-F1 for taxonomy, path-level accuracy, evidence-support rate, controlled-vocabulary rate, description compliance, abstention coverage, and p95 latency/cost. Publish 10 representative error cases and a confusion matrix of sibling classes.

07Competitive Differentiation

Public hackathon postmortems for this exact industrial niche are scarce. The strongest public analogs show what decision-makers reward: an immediately useful workflow, a visible quality mechanism, and credible scale evidence.

Salsify Partner Hackathon winner: Sitation

What

The winning demo combined structured product attributes with GPT-3 to generate long-form product content and translate it into multiple languages. Salsify described it as a balance of practical value and cutting-edge sophistication.

Why here

The lesson is not "use an LLM." It is: connect the model to a real PIM/workflow, start from structured facts, show several channel outputs, and solve a painful catalog bottleneck.

SOTA path

Make the live demo upload a CSV, process real rows, show official source evidence, then export five compliant variants plus review flags. Avoid a pre-scripted product example.

Unilog CX1 Product Content and Vendor FAQ

What

Unilog positions CX1 around over 10 million active products, vendor-managed content, PIM, taxonomy/attribute organization, and content services. Its FAQ says vendor data is reviewed, classified into a master taxonomy, transformed, and syndicated.

Why here

This is the audience's benchmark. A winning submission should speak in the language of master data, coverage, governance, refresh, and syndication rather than only model quality.

SOTA path

Present a catalog-operations view: source freshness, coverage by manufacturer, confidence bands, review queue, taxonomy version, provenance completeness, and reproducible re-runs. Show how the pipeline would scale beyond the demo file.

Rexel + Akeneo/Unifai ETIM case

What

Rexel had over 2.5 million products and 800,000 lacking ETIM classification. The public case reports 12,000 ETIM classifications benchmarked in three months, 98% alignment with its internal algorithm, and 10% annual categorization growth versus 1% before.

Why here

It supplies a very relevant industrial-distribution scale and a judge-friendly metric: audited agreement against an existing process, not a vague model score.

SOTA path

Mirror the structure: compare your system to a transparent baseline, audit disagreements, show what the human could not decide, and measure throughput plus quality rather than only accuracy.

GS1 US National Data Quality Playbook

What

A governance playbook centered on one source of truth, data acquisition, validation, review/reject/synchronize workflows, and lifecycle maintenance.

Why here

It gives a standards-oriented vocabulary for completeness, validation, synchronization, and ownership. That makes the demo feel like a credible PIM component instead of a one-off enrichment script.

SOTA path

Expose an approval lifecycle and data-quality scorecard. Store source revision and refresh timestamps; never overwrite a verified field without retaining the prior value and reason.

Mime on Devpost

What

A recent public hackathon-style product that crawls a store, enriches product data semantically, generates search-oriented JSON, and exposes it through a simple integration. Its writeup emphasizes semantic retrieval and an agent-ready product layer.

Why here

It shows the current competition is not merely data cleaning; teams frame enrichment as a retrieval and agent-consumption advantage.

SOTA path

Differentiate with hard trust constraints: official manufacturer-only evidence, exact field citations, controlled vocabularies, classpath reasoning, and a measured review policy. Pair data quality with better downstream retrieval.

Salsify OpenAI Accelerator

What

A follow-on production-oriented example of pairing crafted prompts with trained datasets to create descriptions, feature bullets, and HTML at catalog scale.

Why here

It reinforces that generation earns attention only when it is tied to reusable templates, data sets, and PIM workflow integration.

SOTA path

Make the output contract channel-specific and deterministic. Include a downloadable JSON/CSV, not just a pretty page, and demonstrate one failed row being routed to review.

Winning narrative: "We do not hallucinate catalog facts. We resolve entities as a graph, retrieve only official manufacturer evidence, extract with citations, verify at field level, abstain under uncertainty, and compile channel-ready content. Here are our measured numbers and our failure cases."

Recommended Architecture

A maximally competitive design combines deterministic parsing, learned retrieval, agentic evidence gathering, constrained extraction, and calibrated review. Complexity is intentionally accepted because the goal is leaderboard and judge impact.

1. Intake and normalization

Parse CSV/XLSX rows. Preserve raw input. Detect MPN spans, dimensions, quantities, UOMs, model suffixes, brand mentions, distributor codes, and likely product type. Create raw and expanded text views; never replace the raw view.

2. Typed entity graph

Resolve product brand and manufacturer separately. Candidate generation uses exact alias, RapidFuzz, phonetic/character keys, Entity Embed ANN, Wikidata/BrandNERD/Open Product Data priors, and MPN compatibility. Final scoring uses Splink-style evidence plus a cross-encoder/LLM pair judge. Store parent/sub-brand/legal/distributor edges with provenance.

3. Hierarchical taxonomy retrieval

Index every Dept/Class/Fine path with definitions, synonyms, sibling contrasts, required attributes, and examples. Retrieve top 20 candidates using BM25 plus embeddings over raw and expanded text. Re-rank with a domain expert and use a strong LLM only to compare candidates. Mask invalid child paths.

4. Manufacturer-only research planner

Build an allowlist from the resolved manufacturer's official domains. Search by exact MPN and product family. Follow official product pages to linked PDFs, manuals, technical data sheets, and CAD/spec assets. Reject marketplace, retailer, distributor, and price-comparison pages at ingress.

5. Document ensemble

Fetch and content-hash HTML/PDF assets. Run Docling native parsing, OCR/layout parsing, and table recognition in parallel. Keep page/region/cell coordinates. Use a vision model only for low-confidence or conflicting regions.

6. Evidence-grounded extraction

For the taxonomy-derived schema, extract label/value/UOM triples with Instructor or strict JSON Schema. Attach source URL, source hop chain, page, bbox, char span, snippet, parser, model, and evidence hash. Reject any value with no exact support.

7. Verification and calibrated decisioning

Run independent extraction passes. Verify each field as supported, contradicted, or not_found. Check MPN, numeric values, UOM conversions, permitted values, class requirements, and source domain. Calibrate auto-accept/review/reject bands on the gold set using risk-coverage or conformal thresholds.

8. Description compiler and export

Freeze verified facts. Generate five variant candidates from typed slots. Apply grammar/schema constraints where useful, then exact character/formula validation and deterministic repair. Export JSON and CSV with per-field provenance, per-variant compliance, confidence, and review reasons.

02Product Taxonomy Classification From Short Noisy Text

The input is closer to a search query than a clean product title. Candidate retrieval against the closed taxonomy should be cheap and high recall; a stronger model should only adjudicate a small, explainable candidate set.

Amazon dual-expert classification

What

A domain expert fine-tuned on catalog data produces top-K categories; a general LLM expert compares those candidates and selects the final category. The paper reports 10,000 human-reviewed products per locale and gains of about 3.8 to 4.0 percentage points over the baseline across locales.

Why here

It maps exactly to a closed Dept > Class > Fine taxonomy while keeping the expensive reasoning call small.

SOTA path

Train a domain encoder on the hackathon taxonomy and manufacturer-language corpus. Retrieve top 20 leaves using title/MPN/expanded jargon embeddings plus lexical search; have a strong judge compare only those leaves using sibling definitions and required attributes. Measure leaf accuracy and ancestor accuracy separately.

Deep Hierarchical Classification for E-commerce

What

A hierarchy-aware classifier that shares representations according to the category tree and uses a combined loss to penalize hierarchical errors.

Why here

A wrong fine class under the correct department is less damaging than a wrong department. The loss and evaluation should reflect that instead of treating all labels as equally distant.

SOTA path

Use hierarchical softmax or constrained decoding with valid child masks. Train with path-aware loss; report exact-path accuracy, level-wise accuracy, lowest-common-ancestor distance, and top-k candidate recall.

HierCat at Facebook Marketplace

What

A dual-encoder query categorization approach with hierarchical inference, weak supervision from search engagement, cross-language transformer pretraining, and taxonomy text representations.

Why here

Manufacturer catalog labels are often sparse or noisy. Weak supervision can scale from existing mappings, but the model must stay aware of the taxonomy hierarchy and unseen categories.

SOTA path

Use positive/negative pairs from labeled examples and near-sibling negatives. Add a taxonomy encoder for path text, sample hard negatives at the same parent, and use evaluator-uploaded data only for inference unless labels are explicitly provided.

Large-scale multi-class hierarchical categorization

What

An e-commerce giant trained on around 150 million products and a five-level taxonomy with 28,338 leaf categories; first prediction matched merchant assignments 81% of the time in the reported setup.

Why here

It is a useful scale benchmark and a reminder that a closed taxonomy is a retrieval/indexing problem as much as a classifier problem.

SOTA path

Build an offline taxonomy index with descriptions, synonyms, sibling contrasts, required attributes, and positive examples. Cache embeddings, use ANN plus BM25, and version the taxonomy so score changes are reproducible.

Amazon LLM-based dual expert paper 0.972 / 0.969 / 0.968 / 0.925

What

The paper's reported dual-expert metrics are materially above fastText, BERT, XLM-R, and the domain expert alone on its evaluation table.

Why here

It gives judges a credible reason for using two models: a specialist for recall and a general model for fine-grained boundary decisions.

SOTA path

Show the candidate list, scores, final decision, and one-sentence sibling comparison in the UI. This makes the taxonomy decision inspectable instead of presenting an unexplained LLM answer.

MaintNorm industrial short-text normalization plus Golden-Retriever jargon expansion

What

MaintNorm introduces 12,000 noisy industrial maintenance examples and reports a 95.8% universal error reduction rate. Golden-Retriever uses reflection to identify jargon and abbreviations, resolve meanings from a domain dictionary, and expand the query before retrieval.

Why here

Inputs like DCB518ASTS06G, 1/2x18, 6pc, grit, and brand codes contain compressed technical language that generic embeddings may interpret poorly.

SOTA path

Keep the raw string and build a parallel normalized view: tokenized MPN, dimensions, quantities, units, abrasiveness/grit terms, tool family, and controlled expansions. Retrieval should query raw plus expanded variants, but extraction must cite the original source text.

Taxonomy rule: never let an LLM invent a classpath. It may rank or choose only from retrieved taxonomy IDs. If the top candidates are close or required class attributes are absent, emit the best candidate with an explicit low-confidence review flag rather than silently overclaiming.

03Structured Extraction From Official Web / PDF Sources

The winning implementation is a document pipeline plus a grounded extractor. JSON validity is necessary but not sufficient: every value must point to an exact source span or PDF region, and a missing fact must remain missing.

Google LangExtract

What

An open-source extraction library with few-shot/schema guidance, chunking and multiple passes for long documents, and post-processing that aligns extracted text to character intervals. Un-grounded extractions can be represented with a null interval and filtered.

Why here

It is almost the desired field-level provenance contract: label/value plus exact span, not just a document URL.

SOTA path

Use one extraction record per attribute value: normalized label, raw value, normalized value, UOM, source URL, page, bounding box, character offsets, source hash, and evidence snippet. Re-fetch and exact-match the span before accepting it.

Instructor

What

Pydantic-backed structured outputs with type checking, custom validators, semantic validation hooks, and automatic retry with validation feedback.

Why here

It gives a clean typed contract for the attribute schema and retry behavior when the model emits invalid UOMs, malformed values, or forbidden fields.

SOTA path

Put business rules into validators: permitted label, UOM compatibility, numeric parseability, enum membership, exact URL domain, non-empty evidence span, and no value without a source. Retry only the failing field or page chunk.

Outlines, LLGuidance, and OpenAI Structured Outputs

What

Constrained generation systems that enforce JSON Schema, regex, or context-free grammar at decode time. LLGuidance reports about 50 microseconds CPU time per token for a 128k tokenizer in its README; OpenAI Structured Outputs guarantees schema adherence on supported models.

Why here

These mechanisms eliminate malformed envelopes and invalid enum members before downstream code sees them.

SOTA path

Use constrained decoding for structure, then semantic validators for truth. Encode permitted attribute labels and UOMs as enums where feasible, but do not put a huge taxonomy or full product vocabulary in a prompt; retrieve a narrow allowed set first.

Docling Technical Report

What

IBM's open-source PDF conversion stack, built around DocLayNet layout analysis and TableFormer table structure recognition, with a small resource budget and structured document output.

Why here

Manufacturer spec sheets often mix text, tables, multi-column layouts, drawings, and scanned pages. Plain PDF text extraction destroys the relation between a value and its label.

SOTA path

Run native-text extraction and OCR/layout extraction in parallel. Route tables through TableFormer or PaddleOCR PP-StructureV3, compare cell grids, and pass cropped table regions to a vision model only when structure confidence is low.

Table Transformer / PubTables-1M

What

Microsoft's table detection and structure model, trained around PubTables-1M, a nearly one-million-table dataset. The associated GriTS metric evaluates predicted tables as matrices and handles topology, location, and content.

Why here

Spec tables are the highest-value source for technical attributes. GriTS is a better table-quality signal than plain character overlap.

SOTA path

Compute table confidence from detection, cell topology, OCR agreement, and downstream label/value validation. Fine-tune or select models on a small manufacturer-spec-sheet set; retain page coordinates for every cell.

PaddleOCR PP-StructureV3

What

A modular OCR and document pipeline with layout detection, text recognition, table classification, cell detection, and HTML output. It supports targeted fine-tuning and multiple model choices.

Why here

It is a strong fallback for image-only or poor-quality manufacturer PDFs, where a single text parser will miss values.

SOTA path

Use it as a second parser for scanned pages. Fuse OCR tokens with coordinates, detect conflicts against Docling/TableFormer, and send only disagreement crops to a vision-LLM adjudicator.

Multi-hop provenance contract: search result -> official product page -> linked PDF -> page/cell/span. Store every hop as a provenance edge and enforce an allowlist of manufacturer domains. A source URL alone is not evidence; a URL plus content hash, page/region, and re-fetchable snippet is.
